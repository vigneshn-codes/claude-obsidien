— Knowledge Strategy Comparison —
Obsidian KB vs RAG vs Fine-tuning
⬡

Obsidian KB

This project's approach

How it works: Markdown vault + CLAUDE.md OS. Claude reads full context at query time via structured wiki pages.
Setup cost: Low — write markdown files, define CLAUDE.md rules. No infra.
Update speed: Instant — edit a .md file, Claude knows it next query.
Knowledge depth: Full — entire vault fits in context; no retrieval gaps.
Best for: Personal/team knowledge bases, books, niche domains.
Limitation: Scales to context window (~200K tokens); huge corpora need chunking.
🔍

RAG

Retrieval-Augmented Generation

How it works: Embeds docs into a vector DB. At query time, retrieves top-K similar chunks and injects into Claude's context.
Setup cost: Medium — needs embedding pipeline, vector DB (Pinecone, pgvector), chunking logic.
Update speed: Fast — re-embed and upsert changed docs. No retraining needed.
Knowledge depth: Partial — only retrieved chunks visible; cross-concept reasoning may miss connections.
Best for: Large doc corpora (10K+ pages), production search, customer support bots.
Limitation: Retrieval can miss relevant chunks; hallucination risk if top-K is wrong.
⚙️

Fine-tuning

Model Weight Adaptation

How it works: Continues training base model on your data. Knowledge baked into weights — no runtime injection needed.
Setup cost: High — needs labeled data, GPU time, eval pipelines, and hosting a custom model.
Update speed: Slow — any knowledge update requires a new training run (hours to days).
Knowledge depth: Behavioral — best for tone, style, format, task patterns. Not reliable for factual recall.
Best for: Consistent output style, domain-specific reasoning patterns, specialized task formats.
Limitation: Can't easily update facts; risks catastrophic forgetting; expensive to iterate.
